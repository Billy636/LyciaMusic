# AMLL 官方优先重构

重构分支：`amll-official-lyrics-refactor`；集成目标：`dev`。本次重构不调整音频引擎、封面区和用户已有的其它界面改动。

## 依赖与边界

- `@applemusic-like-lyrics/core` 固定为 `0.6.0`。
- `@applemusic-like-lyrics/lyric` 固定为 `1.1.0`，`@applemusic-like-lyrics/ttml` 为 `1.0.1`。
- 删除未使用的 Vue 绑定、旧 WASM 入口和对应构建插件。
- 已确认无生产消费者后，删除旧 `get_song_lyrics_payload`、Rust 结构化解析器及 `amll-lyric` 依赖。Tauri ACL 已同步放行新的 `get_song_lyrics_source`。

## 当前数据流

1. `get_song_lyrics_source` 只负责本地/内嵌/WebDAV/缓存来源读取，返回原文、格式提示和不含认证信息的来源路径。
2. `officialParser.ts` 调用官方格式解析器；只保留有明确样本支持的兼容处理。
3. `state.ts` 保存一份毫秒制原始歌词数组。保留原文及解析诊断，异步结果通过请求 ID 防止串歌。
4. AMLL 使用显示副本；轻量、桌面和任务栏由同一数组投影为现有秒制模型。原始词尾、时间间隙、对唱、背景和注音不会在转换中重新猜测。

AMLL 和格式解析分别分包，普通歌词数据加载不需要一起加载重型渲染器。

## 官方能力与少量适配

横排渲染使用 `DomLyricPlayer` 的公开 API，不继承改写布局，不访问高亮集、滚动状态或内部弹簧。删除旧 `PatchedLyricPlayer` 和手工罗马音 DOM 补丁。竖排使用下文的局部坐标适配，仍由官方引擎负责布局、时间和动画。

- 上游负责滚动、分组、间奏、逐字动画、暂停/恢复以及普通尺寸观察。
- `amlLyricPlayerRuntime.ts` 只负责播放时钟、显式跳转、低功耗和生命周期。
- 普通进度采样与 `clockRevision` 校准不会由本地包装器强制重置手滚；`seekRevision` 才明确跳转。上游自己的自动 seek 检测仍保留。
- `sourceStartTimeMs` 仅添加在显示副本上，点击歌词使用原始时间，避免把上游动画提前量当成真实起点。
- `LyricsAppearancePanel` 独立管理设置。四个滑块通过 `useLyricsAppearanceDraft` 即时预览、180ms 合并保存，关闭和卸载时提交。
- 字体/字号使用样式与官方变量；行间 padding 为官方 `0.4em` 的 50%–300%，不再重写行位置算法。对唱继续使用原生右对齐。
- 局部外观选择器依赖固定的 core 0.6 样式结构，并有已发布 CSS 的契约测试。以后升级仍需检查这些少量选择器。

## 解析规则与有意变化

### 竖排封面歌词

入口为播放页底部“歌词样式” → 面板顶部“排版方向” → “竖排”。`playerWritingMode` 默认横排，沿现有 `player_settings` 保存和恢复；旧设置缺少此字段时仍保持横排。竖排使用 AMLL，回到横排会恢复原先选定的 AMLL / 轻量效果。

`verticalAmlLyricPlayer.ts` 是 `DomLyricPlayer` 的局部适配子类：舞台宽高互换，中文等字形通过内层 grapheme 节点保持直立，拉丁词组通过内层文字节点校正朝向，保留原生动画节点和度量。原始逐字遮罩、强调字符动画、弹簧、模糊、对唱、背景人声和时间戳均留在官方引擎中，不修改依赖文件。

竖排的“移动方向”支持“向左 / 向右”，默认向左。向右模式使用 90° 旋转，下一句在左侧；向左模式使用轴交换矩阵，下一句在右侧，中文字形逆变换及拉丁文本反射抵消保证文字不镜像。两种模式每句均从上往下读、高亮均从上往下推进。`playerVerticalScrollDirection` 沿现有设置保存，切换时按当前播放时间重建坐标视图，不改变播放进度。横向滚轮按各自坐标方向映射。

句内逐字高亮继续使用官方按词起止时间驱动的遮罩，竖排坐标使遮罩从上往下推进。字词上浮和强调字符的位移通过 Web Animations API 的 `getKeyframes` / `setKeyframes` 校正到屏幕上下方向，避免舞台旋转后变成左右晃动。保留同一动画对象、时间、缓动、缩放和辉光，不触碰遮罩动画或整列弹簧；暂停、跳转和低功耗仍由 AMLL 调度。横排保持官方动画。

适配仅覆盖可继承的 `buildLyricGroups`，并包装公开的 `rebuildElement` 和 `updateMaskImageSync` 路径。官方长句平衡器量测时，在同一调用栈内暂时撤销舞台旋转并立即恢复，避免屏幕矩形的宽高交换造成错误换列。普通整行歌词平衡后会重新装饰字形，虚拟行重建仍走同一路径。未来升级 core 时需复核这些方法及现有 DOM 样式结构。

歌词区域左右渐隐；“歌词间距”显示为“列间距”，“靠左 / 居中 / 靠右”在竖排中显示为“顶部 / 居中 / 底部”。点击歌词使用原始时间跳转，暂停和低功耗沿用同一个运行时。鼠标滚轮和横向触控板可翻列；触屏拖动目前仍沿用上游的纵向手势。

### 原始格式处理

- 普通 LRC、增强 LRC、ESLRC、YRC、QRC、加密 QRC、LYS 交给官方解析。TTML 使用官方丰富类型和转换器，优先已有中文翻译，其次采用官方首条翻译。
- 同时间未标注多行按照用户选定的读取顺序归组，设置入口在播放页歌词样式的“歌词偏移”下方；不做语言猜测。默认是“原文 → 翻译 → 罗马音”，支持全部六种排列。
- 三行使用完整排列；两行删除排列中的“罗马音”并保持剩余两项相对顺序（例如“翻译 → 原文 → 罗马音”派生为“翻译 → 原文”）；单行始终作为原文。
- `[main]`、`[original]`、`[tr]`、`[romaji]` 等明确标记优先于选择。部分标记锁定对应角色，其余按剩余角色的顺序填入；标记冲突、超过三行或无法唯一归属时保留原内容并给出诊断。背景、对唱、空白结束标记不按语言行数套用。
- 翻译/音译的原逐字时间分别保存在 `translationWords` / `romanWords`。官方渲染的翻译使用整行副文；逐字音译通过共享的 `romanization.ts` 做最小时间归并后填入官方 `romanWord`，普通整行 LRC 仍保留 `romanLyric`。
- LRC 按物理行调用官方解析，防止上游把后续同时间逐字行压成整行文本。明确的增强标签缺尾、`v1:`/`v2:`、重复时间戳等由小范围适配处理。
- 原文最后一个有效 `[offset]` 按既有产品方向只应用一次；用户同步偏移仍在播放时钟边界处理，空间 X/Y 是独立设置。
- 已知行词结束时间保持不变；缺少结束标记时，使用下一起点/歌曲时长，仍无法确定时使用有界回退。没有时间戳的原文不伪造逐字时间。
- 显式空时间行保留供桌面/任务栏间奏清屏，AMLL 显示副本滤除该空记录。
- 主声和背景按组排序，背景早于正文开始时仍保持相邻。
- 官方 TTML 解析器对标签前缀、默认命名空间及 iTunes key 有要求；适配仅规范化 TTML 元素命名空间、补内部缺失 key，原文和时间保持不变。

旧 Rust payload API、解析器及其专属测试已退出；原文读取/编辑接口和格式样本仍保留。旧的、不在生产路径上的前端 parser/classifier/compat 及其过时规则测试已退出。设置迁移测试与有价值的格式样本已迁入新入口测试。

## 字号调整回归修复

用户在真实桌面测试中遇到 `ResizeObserver loop completed with undelivered notifications.`。这是浏览器延后尺寸通知时发出的 `window.error` 事件；旧入口将其直接升级为致命错误并覆盖整个应用 DOM。

新入口只将无异常对象且消息精确匹配的 ResizeObserver 通知按非致命布局诊断处理，保留有次数的限流日志。真正的脚本异常、Vue 异常、Promise 拒绝和启动失败仍走原报错流程。不会全局屏蔽 ResizeObserver，也不会修改上游观察器。

同时修正字号提交时的无关数据失效：设置存储替换对象时，独立的布尔 computed 隔离翻译/罗马音开关，字号、间距、位置和其它设置变化不会重新分配歌词数组或触发 `setLyricLines` 全量重建；换歌和真正切换副行仍更新。回归测试使用实际 Pinia 设置存储和既有设置代理验证数组引用及 renderer watcher 次数。

## 手动读取顺序

入口：播放页 → 歌词样式 → 歌词偏移下方的“歌词读取顺序”。“默认”在左且初始选中，不重置用户已有的默认排列或单曲覆盖。点击顺序框向右展开与字体菜单一致的玻璃浮层，原文、翻译、罗马音从上到下排列，拖动三行即可排序；不再列出六组预设选项，也不显示原先的两行说明。

- “默认”作用于没有单曲覆盖的歌曲；修改默认不会覆盖已单独设置的歌曲。
- “当前歌曲”只给当前 `song.path` 保存覆盖；可清除后跟随默认。范围不会因为开始播放或换歌自动从“默认”跳到“当前歌曲”。
- 拖动时仅预览顺序，松手在浮层内才保存；取消、松手在浮层外、切换歌曲/范围时不提交过期拖动。键盘上下箭头也可调整顺序。右侧浮层不会被抽屉滚动区域裁切，并在打开时关闭字体菜单。
- 保存沿用 `player_settings`，切换立即对缓存原文重新解析，不再访问磁盘、不写回原文件、不改变播放进度。连续切换/切歌时会丢弃过期解析结果。
- LRC家族、YRC和QRC的无角色同时间组可使用设置；TTML和LYS继续尊重原生角色/声部结构。TTML不因手动顺序变化重建。
- 本轮使用精确的原始行时间分组，不做模糊时间或语种评分；负文件offset将多行夹到0时，不会把原本不同时间的句子误合并。
- 这是读取身份设置，不是屏幕上下位置设置，动画和排版仍由官方AMLL负责。

真实解析/状态测试覆盖三行日语、两行英文、单行和显式标记混合，以及“罗马音 → 原文 → 翻译”和“翻译 → 原文 → 罗马音”的两行差异与即时切换。

## 逐字音译一对多与防遗漏

LRC 归组和 TTML 的官方转换共用同一层纯数据适配；没有增加 DOM 补丁、动画或发音识别规则。

- 每个非空音译片段按时间归入能够覆盖它的非空正文词，允许边界 2ms 精度差；多个候选时必须有唯一的最大实际重叠。明显跨词、落入空隙、歧义或归属逆序都不强行匹配。
- 一个正文词可接收多个音译片段，例如“本”接收 `ho + n`。正文词缺少音译时留空，不使后面的词按数组位置错位。
- 成功前检查所有片段按原顺序完整保留一次，包含重复音节和分隔空格；失败则清除部分逐字结果、保留完整整行音译并记录诊断。正文空格不能承载非空音译，避免上游将其当纯文本节点而丢失注音。
- `romanWords` 的原始文字和时间、正文/译文、背景/对唱关系、ruby 等均保持不变；普通整行音译仍用 `romanLyric`，避免 AMLL 非逐字路径下消失。
- 合并后的 `ho n` 使用“本”的时间段由官方一起高亮；这不是为 `ho`、`n` 新增独立的逐音节动画。
- 两段用户原始歌词保存在 `fixtures/romanizationTiming.ts`，实际解析测试覆盖不一致词数、空音译槽、1ms 边界与全部 15 个音译片段完整保留；TTML 测试同时覆盖上述规则与失败回退。

本次验证：歌词/播放相关 392 项测试全部通过，类型检查、目标 ESLint 与差异检查通过。全量 1289 项通过，仅保留此前 `AppBrand.test.ts:50` 的间距期望差异（`gap-2.5` / `gap-2`），未修改该无关界面工作。真实 WebView 动画效果仍由用户使用两段原曲验收。

## 播放页左右抽屉

歌词样式改为 `body` 上的固定左侧抽屉，不再依靠歌词列的宽度反向计算位置：贴左边缘滑入，右上/右下保留 24px 圆角。播放队列仍从右侧滑入，并镜像保留左侧圆角。

两者共用 `playerSidePanel.css`：相同的 320px 宽度、上下留白、半透明黑色背景、白色文字、描边、阴影、滚动条及动效。标题/关闭入口固定在顶部，内容区单独滚动；队列保留原来的 69px 虚拟行高和播放/移除/清空确认行为。在非播放页，队列只加深底色以保持白字在浅色页面上的可读性。

歌词样式关闭仍提交滑块草稿；退出详情时立即关闭传送到 body 的面板。Esc 先关闭展开的读取顺序或字体菜单，再关闭面板，不会穿透退出播放页或沉浸模式。右侧队列遮罩保留底部 96px 操作区，不模糊整页，也不挡住播放按钮。动效遵守减少动态效果的系统设置。

相关 342 项回归、目标 ESLint 和类型检查通过；全量 1307 项通过，唯一失败仍为上述未修改的品牌间距测试。最终滑入观感、圆角和半透明效果需在真实桌面窗口手动验收。

后续交互调整已将读取顺序改为右侧拖动排序，并移除临时原生调试显示入口、隔离构建配置及配套样本生成脚本。已有生成样本、用户数据与可执行文件均未删除；浏览器 smoke 保留。按用户要求，本次仅修改源码及对应测试断言，不执行测试、类型检查、lint 或打包，现有 exe 未更新。

## 待播时的样式入口

样式面板由 `PlayerDetail` 独立挂载，不再放在受歌词状态控制的 `LyricsView` 内，也不再以歌词行数作为可用条件。刚恢复歌曲但尚未播放、歌词加载中、无歌词或加载失败时，均可先调整并保存样式；切换到内嵌队列也保留该入口。无歌曲时仍可改默认样式，单曲读取顺序保持禁用。

字号、间距、偏移的即时草稿由播放页转交 `LyricsView`，AMLL 与轻量渲染器继续使用同一份预览；歌词稍后加载或视图重新挂载时也读取已设置的值。该调整不触发加载音频或自动播放，保留原来的无歌词信息展示和关闭面板时提交草稿的行为。本次同样未执行测试或打包。
