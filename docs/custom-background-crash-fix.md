# 自定义背景切换闪退修复

## 问题与原因

2026-10-14，已安装的 Lycia 1.5.2 在编辑自定义背景并返回页面后闪退。
Windows 记录的异常为 `0xc000001d`，转储显示 Tauri 在复制
`DetachedWebview` 时触发了内部引用计数的终止检查。

项目使用的 `tauri-runtime-wry` 2.9.3 按值复制主线程上下文，其中的
Tao Windows 窗口目标包含非原子 `Rc<EventLoopRunner>`。后台背景任务
复制或释放应用、窗口句柄时，可与主线程竞争同一个引用计数。

通过程序调试接口交错执行背景准备和取消请求，原逻辑两次出现堆损坏
（`0xc0000374`）。这是压力复现；异常位置与下午的原始转储不同，
不能将每个内存释放位置当成最初破坏内存的位置。

## 修复

通过 Cargo 本地补丁固定使用仓库中的 `tauri-runtime-wry` 2.9.3：

- 窗口上下文改为 `Arc<SharedMainThreadContext>`，跨线程句柄复制和释放
  只增减外层原子引用计数。
- 最后一个引用在后台线程释放时，将内部资源的销毁交回主线程。
- 销毁任务通过 `ManuallyDrop` 持有资源，防止退出时未送达的任务在
  后台线程意外释放内部 `Rc`。无法执行的任务仅保留这一个共享上下文，
  由进程退出回收。

未改动背景预览、缓存、图片处理和请求淘汰的业务逻辑。上游来源、许可证
和补丁维护说明见 `src-tauri/vendor/tauri-runtime-wry-2.9.3/LYCIA_PATCHES.md`。

## 验证

- 当前工作区通过 `cargo check --locked --offline`。
- 使用安装版构建前最后一次提交 `45f767f` 的业务源码，接入正式本地补丁，
  生成带独立应用标识的 Windows release 构建；未使用鼠标、键盘或截图操作。
- 20 轮顺序执行背景预览准备、取消、更新主题和返回页面，未崩溃。
- 5,024 次缓存命中的并发准备／取消请求，全部完成，未崩溃。
- 清空独立缓存后，4,000 次改变目标尺寸和模糊参数的并发请求全部完成，
  未崩溃。两组共 9,024 次请求，无非预期接口错误；过期请求按预期淘汰。
- 背景请求尚未完成时退出应用，原生调试器确认正常退出。

依照项目约定，未新增测试文件。复现使用独立数据库、复制的背景缓存图片
和临时音频。原始 Windows 崩溃转储保留；此次创建的临时诊断数据可在验证后
按独立目录清理。

以上验证覆盖当前 Windows 环境，不等同于穷尽所有线程时序或平台。
后续升级 Tauri 时须审查并迁移补丁，防止本地修复被新依赖版本绕过。
