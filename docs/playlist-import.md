# 外部歌单导入与文件关联

入口：**我的歌单 → 导入外部歌单**。导入后会打开生成的歌单；匹配电脑上的本地音乐，以及已启用、已索引的远程曲库歌曲。不下载平台歌曲，也不修改音频标签。

## 支持的来源

| 来源 | 行为 |
| --- | --- |
| 网易云音乐公开歌单分享链接 | 读取原始顺序和歌曲 ID，按需分批补齐歌曲详情 |
| QQ 音乐公开歌单分享链接 | 读取歌曲、歌手、专辑和时长；平台限制或数量不一致时显示提示 |
| M3U / M3U8 | 按文件中路径和顺序读取，可选择持续关联 |
| 椒盐等工具导出的逐行路径 TXT | 按文件路径清单读取 |
| CSV / JSON / 文本歌曲清单 | 根据歌名、歌手等信息匹配本地曲库 |

分享文字中可以包含链接。支持网易云的 `#/playlist?id=…`、`playlist?id=…`、163cn.tv 短链接，以及 QQ 常见歌单链接和分享跳转。私有、需要登录、接口受限的歌单需要改用清单文件。不会要求用户提供账号密码或 Cookie。

平台返回的歌曲数与声明数量不一致时会显示警告，来源记录保留实际条目和声明总数。单次最多 10000 条，文件上限 16 MB，最多同时关联 500 个歌单文件。HLS 网络流媒体 M3U8 不作为本地歌单解析。

## 导入与自动匹配

1. 选择链接、文件或粘贴清单，点击“读取并匹配”。
2. 查看已匹配、待补齐和跳过的数量；可以仅显示待确认项目。
3. 自动采用通过歌名、歌手、专辑、时长和版本检查的最佳候选，无需逐首确认；候选同分也会自动选择。
4. 可直接创建歌单。也可选用其他候选、搜索曲库、试听或跳过条目；导入后可正常移除不需要的歌曲。
5. 点击“创建歌单”。未匹配信息保留在导入记录中，不会伪造歌曲文件。

预览中，候选框前的绿色圆点表示精确匹配，黄色表示匹配信息存在差异，红色表示缺失歌曲；悬停圆点可查看具体原因，不再在候选框下显示状态文字。黄色候选仍默认选中，可以直接创建歌单。顶部保留“全部”，并用绿、黄、红三个带数量的按钮分别筛选对应状态，移除单独的总数统计。试听使用播放三角图标，当前歌曲播放时切换为暂停图标，再次点击可暂停或继续；跳过使用 X 图标。

普通导入歌单可自由编辑。详情中的“查看记录 / 补充匹配”可以在补齐音乐后继续匹配；新补齐的歌曲追加到歌单，已有手动顺序及用户移除的歌曲不会被重新覆盖。已保存的匹配会用于之后的导入，保存前仍检查文件是否可用。

### 自动匹配规则

- 保留原始信息，额外识别主歌名、括号中的跨文字别名、feat./ft. 合作署名，以及平台返回的歌名别名。不会无条件删除括号中的曲目编号或同语言副标题。
- 歌手匹配支持括号别名、额外合作署名，以及初音ミク / 初音未来 / Hatsune Miku 的常见写法。
- 有歌手信息时，歌名完全一致或相近且歌手相符就自动采用最佳候选；模糊歌名需要更强的歌手、专辑或时长佐证。仅歌名清单可自动采用完全一致或相似度至少 90% 的最佳候选。明显版本冲突、曲号不同、时长严重不符或仅弱相关的歌曲不会被强行加入。
- 候选排序权重：歌名 62%、歌手 24%、专辑 6%、时长 8%；缺失项不计权重。分数用于排序，不代表正确概率。
- 优先采用排序第一的候选；同分时依次优先本地文件、无损格式、稳定路径顺序，不再因为多份编码要求用户确认。
- 远程歌曲保留 `remote://` 标识，通过现有远程播放流程播放；匹配时不逐首联网下载。连接可用性仍取决于播放时的网络及远程服务。
- 旧歌单再次打开“查看记录 / 补充匹配”时，原先未匹配的条目会自动尝试新规则；保留已有匹配、跳过记录和歌单中的移除操作。

### 自定义匹配条件

预览右上角的“自定义匹配”提供“默认、歌名、歌手、专辑、时长”。默认选中“默认”，沿用上述算法；取消“默认”后可以勾选“歌名”，勾选歌名后才可选择其余三项。重新选中“默认”会清空并禁用四个自定义选项；取消“歌名”会清空并禁用后三项。点击“应用”对整份清单重新匹配，保留歌单名称和跳过状态，重新自动选择候选，历史选择不会绕过新条件。

自定义模式要求所有勾选字段同时符合，未勾选的字段不参与过滤、排序或黄色提示。歌名采用规范化后的歌名或已识别别名一致，保留歌名中的现场、伴奏等版本区分；歌手按已识别别名核对双方署名，专辑规范化后须一致，时长允许 2 秒误差。例如“歌名 + 专辑”不会因为歌手不同而拒绝候选，“歌名 + 歌手”不会因为专辑不同而变黄。通过所选条件的候选显示绿色并自动选中；同分沿用本地、无损、稳定路径的优先顺序。

来源缺少所选的歌手、专辑或时长时显示黄色圆点，悬停显示缺少的字段，不会把缺失信息当作已符合；所选字段齐全但找不到符合条件的候选时显示红色。条件随歌单导入记录保存，下次打开继续使用。M3U 等路径歌单仍按路径识别，不显示此设置。

## 文件关联

M3U/M3U8 默认勾选“关联源文件，自动跟随文件更新”。

- 相对路径以歌单文件所在目录为基准；支持绝对路径、`file:` 地址、中文和 UTF-8 BOM。
- M3U8 使用 UTF-8；传统 M3U 可读取 UTF-16 BOM 和 GBK，界面提示重新导出 UTF-8。
- 跨设备绝对路径不同，可在读取前设置路径前缀映射，例如 `/storage/emulated/0/Music` → `D:/Music`。
- 关联歌单由文件决定条目与顺序；添加、移除、拖动修改需要先复制为普通歌单，或解除关联。显示排序可以临时调整，不会写回文件。
- 后台监听所在目录，合并约 700 ms 的文件事件，再确认内容稳定；可处理 Syncthing 临时文件替换目标的保存方式。
- 每 30 秒核对一次，补偿遗漏事件、缺失目录和晚到的音乐文件。启动时重新建立关联；不依赖歌单页面保持打开。
- 文件暂不可用或解析失败时保留上次成功内容并显示错误；文件恢复后自动重试。稳定读取成功的空文件会更新为空歌单。
- 歌单先同步、音频后同步时，缺失条目保留在来源记录，音频到达后恢复可播放状态。不会全库重扫。
- 歌单刷新只更新歌单内容，不替换当前播放队列或中断播放。
- 详情提供立即刷新、重新关联文件、复制为普通歌单和解除关联；删除歌单不会删除源文件或歌曲。

文件中重复条目及顺序保留在来源记录和歌单中。当前播放队列沿用应用原有的按路径去重规则。

## 清单格式

CSV 使用表头，歌手可用分号分隔，时长为秒或 `分:秒`：

```csv
title,artists,album,duration
晴天,周杰伦,叶惠美,269
```

也接受常见中文表头：歌名 / 歌曲名 / 歌曲名称、歌手 / 艺术家、专辑、时长。

JSON 可以直接使用歌曲数组，也可以包含歌单名称：

```json
{
  "name": "通勤",
  "tracks": [
    { "title": "晴天", "artists": ["周杰伦"], "album": "叶惠美", "duration": 269 }
  ]
}
```

TXT / 粘贴清单支持每行 `歌名 - 歌手`、`歌手 - 歌名`、仅歌名，或用 Tab 分隔歌名、歌手、专辑。默认结合曲库自动识别字段顺序并直接采用最佳匹配；也可在导入前为整份文本指定格式。若 TXT 每一行都是音频文件路径，则按路径歌单读取。

### GoMusic 网站清单

[GoMusic](https://github.com/Bistutu/GoMusic) 提供上述三种文本格式，复制网站的结果后可直接粘贴，也可保存为 TXT 后选择文件导入。默认“自动识别”会比较正序、反序及完整歌名；歌名内部包含 ` - ` 时，保留首尾两种分隔位置参与比对，单行最多五种解释，不要求用户逐首判断。预览和保存记录使用识别后的歌名及歌手，并保留原始文本方便以后继续匹配。

网站普通模式会去掉部分括号内容。建议勾选网站的详细歌曲名选项，并使用“歌名 - 歌手”，保留歌手和版本信息。仅歌名也会自动匹配，但同名不同歌手无法靠文本可靠区分；同分时沿用本地、无损、稳定路径的优先顺序，不要求人工确认。上游已删除的信息无法还原。

例如 `晴天 - 周杰伦` 与 `周杰伦 - 晴天` 都会尝试对应歌名“晴天”、歌手“周杰伦”；`晴天` 则按歌名匹配。TXT 缺少专辑与时长时，实际分数为 `(歌名相似度 × 0.62 + 歌手相似度 × 0.24) / 0.86`，不会因为没有这些列而额外扣分。括号开头的普通歌名不再被直接当成 JSON；支持 BOM、Windows/Unix/旧 Mac 换行，沿用 UTF-8、UTF-16 与旧编码读取。

## 导出

歌单详情中的“导出 M3U8”使用 UTF-8，优先写入相对路径；跨盘符无法转换时保留绝对路径。关联歌单导出保留源文件中的缺失条目，普通歌单导出当前歌曲列表。导出文件中的歌曲仍需要用户自行同步。

## 实现结构

- Rust `playlist_import/sources.rs`：来源适配、编码与路径解析、平台详情读取、数量警告。
- Rust `playlist_import/matcher.rs`：完整本地曲库索引、候选召回、同一候选的多字段评分、版本冲突与歧义判断。数据库读取后释放锁再计算匹配。
- Rust `playlist_import/watcher.rs`：目录监听、稳定读取、周期核对和带关联版本号的事件；前端忽略旧关联的事件。
- `Playlist.importData`：保存完整来源清单、每个条目的选择、跳过状态、路径映射、关联版本和最近成功时间，沿用已有歌单持久化。
- SQLite `playlist_import_paths`：记录歌单持有的本地路径，让曲库扫描和移除目录时保留仍被导入歌单引用的库外歌曲；不持有源文件写权限。
- 前端 `features/playlistImport`：共享导入入口、后台文件桥接、类型及恢复校验。
- Vue `PlaylistImportDialog` / `PlaylistSourcePanel`：导入向导、自动匹配预览与可选更换、来源状态和文件管理操作。

平台导入采用一次性迁移，不自动覆盖用户之后的本地修改；持续自动更新只用于用户明确关联的文件歌单。所有匹配在本机完成。
